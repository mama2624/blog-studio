# 지연님 블로그 작업실 (blog-studio)

지연님 전용 **반자동 멀티작업실** — **글 용도 3모드**(📝 블로그 10단계 · ☕ 네이버 카페 글 · 🛒 상품·여행 제휴 리뷰)로 원고를 만들고, 그 원고 하나로 **🧵 스레드 타래**와 **🎬 클립·릴스·유튜브 대본**까지 뽑아 스마트에디터·스레드·영상에 붙여넣는 정적 웹앱입니다.
빌드 없이 순수 HTML/CSS/JS라서 GitHub Pages에 그대로 올리면 됩니다.

## 🖼️ 이미지 프롬프트 세트 · ✍️ textless 통일 · ⚡ 기본 모델 상향 (v2.2.3 · 2026-11-19)

크리(@keuli8) 님 진단 3건과 지연님·크리 님 PC 브라우저의 `localStorage` 마이그레이션을 함께 반영했습니다. 잠금(`LOCK_HASH`·`bs.unlock.v2`)과 **v2.2.2 연출표·라이선스·v2.2.1 안전장치 3종은 그대로**입니다.

### ① 원고 속 이미지 프롬프트 세트 — `js/prompts.js` `imagePromptSetFormat()`

젬 지식 제4조는 원고마다 **[썸네일 1·2 복사용 영문 프롬프트 + 목차별 본문 이미지 + 3:1 배너]**를 내라고 하는데, 작업실 `[출력 형식]`에는 그 칸이 없어 세트가 통째로 빠졌습니다. 해시태그 바로 뒤·`## 작업 메모` 바로 앞에 `## 🖼️ 이미지 프롬프트 세트` 칸을 넣고 세 묶음을 원본 순서대로 적게 했습니다(썸네일 1번 타이포형 / 2번 실사 결합형 / 목차 1번~FAQ 직전 목차별 1:1 본문 / 하단 3:1 슬림 허브 배너).

- **우선순위 3번 예외** — "[출력 형식] 외 머리말 금지"가 이미지 프롬프트 세트까지 막지 않도록 "**단, 이미지 프롬프트 세트는 원본 규격대로 출력한다**"를 명시했습니다. `outputRules()` 에도 `6-2` 로 같은 자리를 못박았습니다.
- **블로그 원고 전용** — 카페·제품 리뷰 `[출력 형식]`에는 들어가지 않습니다.
- **앱 처리** — 이 칸은 제미나이에 붙여넣는 작업용이라 화면에는 "🖼️ 이미지 프롬프트 세트 · 화면 확인용(복사본에는 빠집니다)" 박스로 보여 주고, 스마트에디터 복사본·마크다운·글자수(`bodyChars`)에서는 뺍니다(`isImagePromptSection()`).

### ② 썸네일 2번 글자 지시 통일 — `textless`

`thumbnailInstructions()` 의 "사진 위에 한글 문구를 넣어라"와 `BS.IMAGE_GEM.photoPrompt` 의 `textless, no words` 가 정면으로 부딪히고 있었습니다. 젬 원본 원칙대로 **AI는 글자를 그리지 않고 상단 1/3만 비운다(textless)** 로 통일했습니다.

- 썸네일 2번은 `textless, no text, no words, no letters` 로 만들고, 삽입 한글 문구는 "삽입 한글 문구"로 따로 적어 지연님이 스마트에디터·미리캔버스에서 직접 얹습니다.
- 문구 자리는 상단 1/3 안의 좌우 정중앙 그대로입니다. 한글 글자를 그리는 유일한 예외는 썸네일 1번(타이포형)입니다 — `BS.THUMB_RULES`·`BS.IMAGE_THUMB_RULE`·`BS.IMAGE_PRINCIPLES` 도 같은 기준으로 고쳤습니다.

### ③ 기본 원고 모델 `gemini-3.5-flash-lite` + 저장값 1회 전환 — `BS.DEFAULT_TEXT_MODEL`·`BS.MODEL_MIGRATION`

- 기본 원고 모델을 `gemini-2.5-flash`(무료 하루 20편)에서 **`gemini-3.5-flash-lite`(무료 하루 500편)** 로 올렸습니다. 화면 안내도 "gemini-3.5-flash-lite 무료 하루 500편 지원 · 실시간 검색이 필요하면 설정에서 2.5 Flash로 변경" 으로 실제 동작과 맞췄습니다.
- **브라우저 마이그레이션** — 이미 쓰던 브라우저 `localStorage(bs.textModel)`의 옛 기본값 `gemini-2.5-flash` 는 새로고침 한 번으로 `gemini-3.5-flash-lite` 로 바뀝니다. `bs.modelMigrated.223` 플래그로 **1회만** 동작하고, 그 뒤 설정에서 2.5 Flash를 다시 고른 선택은 덮어쓰지 않습니다.
- **검색 미지원 경로** — Flash Lite는 `BS.WEB_SEARCH.unsupported` 라 `webSearchAllowed()` 가 `false` 를 돌려주고 배지(`검색 미지원 모델 → 일반 작성`)만 띄운 뒤 검색 없이 정상 작성합니다. 400/403 이 오면 `geminiText()` 가 tools 없이 한 번 더 부릅니다.
- **폴백 사슬 중복 없음** — `modelChain('gemini-3.5-flash-lite')` = `['gemini-3.5-flash-lite','gemini-3.1-flash-lite']` (같은 모델을 두 번 부르지 않음).

## 🎬 쇼츠 절차형 4단계 연출표 · 🔊 상업 무료 라이선스 · 📅 기억 의존 금지 (v2.2.2 · 2026-11-19)

### ① 쇼츠·클립 절차형 4단계 연출표 — `js/config.js` `BS.SHORTS_DIRECT` · `js/prompts.js`

영상이 '조잡해도 터진' 이유는 화질이 아니라 기획이었고, AI 영상이 "고정 사진"처럼 나오는 원인은 장면을 한 덩어리로 시켰기 때문입니다. 그래서 대본을 30초 네 구간으로 쪼갭니다.

| 구간 | 역할 | 규격 |
|---|---|---|
| 0~3초 | 훅 | 질문 또는 반전 한 문장 — 배경 설명·인사 금지 |
| 4~8초 | 원리 | 왜 그런지 한 줄 — 숫자나 기준 하나 |
| 9~24초 | **절차 4단계** | 각 3~4초 · 한 단계에 동작 하나 · 이름은 동사로(끄기 → 잠그기 → 빼기 → 확인) |
| 25~30초 | 결론 + CTA | 저장·팔로우 중 **하나만** |

- 단계마다 **① 화면 ② 카메라(줌인·줌아웃·회전·패닝·컷·고정 중 1개) ③ 자막 12자 내외 ④ 효과음 1개 ⑤ BGM(유지·고조·정지 중 1개)** 를 따로 적습니다. 같은 카메라를 세 구간 연속 쓰지 않게 막았습니다.
- **🎬 영상 대본 모드(숏폼)** — 출력에 `## 30초 절차형 연출표` 칸이 생깁니다(훅·원리·절차 1~4단계·CTA 7블록 × 6줄). 장면 블록은 그대로 두고, 장면 프롬프트 안에 카메라 움직임을 한 구절로 넣게 했습니다(Flow에 붙일 때 화면이 살아나도록).
- **⚡ 멀티유즈 클립(20초)** — 같은 리듬을 20초로 줄여 `## 클립 20초 연출표` 4줄(0~3초 훅 / 4~8초 원리 / 9~17초 절차 2~3단계 / 18~20초 CTA)로 냅니다. 20초에 25~30초 CTA를 넣을 수 없어 시간만 줄였고, 30초 쇼츠로 늘릴 때는 같은 30초 규격을 쓰라고 프롬프트에 적어 두었습니다. 앱 파서·복사 버튼도「자막 4줄」→「연출표 4줄」로 맞췄습니다.
- **롱폼(3~5분)** — `## 연출표 (장면별)` 한 줄씩 같은 5항목으로 적습니다.
- **결과 화면** — 뽑힌 대본에 **🎬 절차형 4단계 연출표**(화면·카메라·자막·효과음·BGM)와 **🔊 라이선스 확인** 카드가 복사 버튼과 함께 나옵니다. `📋 피클에게 보낼 영상 요청`에도 두 칸이 들어갑니다.
- 3D는 필수가 아닙니다 — 화면은 카드·손·제품·도구처럼 스마트폰으로 찍을 수 있는 것으로 적게 했습니다.

### ③ 기억 의존 금지 — 최신 출처·날짜 기준 — `BS.SOURCE_CHECK` (공통)

모든 프롬프트가 같이 쓰는 `factRules()`에 세 줄을 붙였습니다(원고·카페·제품 리뷰·2단계 검수·스레드·멀티유즈·영상 대본에 동시 적용).

1. 정책·금액·일정·모델명·라이선스·수치처럼 바뀌는 값은 **오늘 기준 최신 공식 문서로 확인한 것만** 쓰고, **출처 이름과 확인 날짜**('2026-11-19 확인 · 기관명')를 함께 적는다.
2. 확인하지 못한 수치·일정은 **추정으로 채우지 않는다** — '약·보통·대략·최근'으로도 만들지 않고 `확인 필요: (항목)`으로 남긴다.
3. 기억과 확인한 자료가 어긋나면 **확인한 자료를 따르고**, 바뀐 시점을 `[기준 시점]`에 적는다.

### 어떻게 동작하나

| 항목 | 내용 |

## 보안 (중요)
- **API 키는 코드에 없습니다.** 지연님이 앱의 `⚙️ 설정`에서 직접 붙여넣고, 그 값은 **이 브라우저의 localStorage에만** 저장됩니다.
- 저장 위치 키 이름: `bs.apiKey` (지우려면 설정 → 키 삭제).
- 깃허브에 올라가는 파일에는 키가 들어가지 않습니다. 다른 사람과 이 페이지 주소를 공유해도 키는 각자 브라우저에만 있습니다.
- 모델 이름 기본값: 원고 `gemini-2.5-flash`, 이미지 `gemini-2.5-flash-image`. 설정의 **모델 목록 불러오기**로 그 계정에서 실제 쓸 수 있는 모델을 확인해 바꿀 수 있습니다.

## 2단계 원고 파이프라인 (v1.6.0 · 2026-11-17)
한 번의 생성 안에서 AI가 지침을 가끔 어기던 문제를 없애기 위해, 원고를 **두 번의 API 호출**로 나눕니다.

| 단계 | 하는 일 | 화면 표시 |
|---|---|---|
| **1단계 초안** | 고른 블로그·주제·옵션으로 10대 규격 초안을 씀 | `1/2단계: 원고 초안을 작성하고 있습니다…` |
| **2단계 전수 검수·수정** | 초안을 지침 처음~끝과 대조해 1차(팩트·수치·금지문구·블로그 개인화·10대 규격·제휴 연관성·긍정사랑 내부링크·제목 7종+추천 제목·사진 배치) → 2차(AI티·번역투·모바일 1~2문장 호흡·불필요한 중복)로 두 번 검수하고, 고친 **최종본만** 돌려줌 | `2/2단계: 지침 처음~끝 대조 검수·수정 중입니다… (오류·누락 점검)` |
| 완료 | 2단계 최종본을 그대로 화면에 올림. `작업 메모`의 `2회 검수` 줄에 실제 수정 내역이 남음 | `✅ 2단계 검수·수정 완료 — 본문 …자` |

### 안전장치 (fallback)
- **2단계가 429(한도 초과)·5xx·시간 초과로 실패** → 1단계 초안을 버리지 않고 그대로 보여 주며, `1단계 초안은 완료됐으나 2단계 자동 검수 중 오류가 발생해 초안을 표시합니다 — (오류 사유)` 안내와 `🔁 2단계 검수 다시 시도` 버튼을 띄웁니다. 버튼은 초안을 그대로 두고 2단계만 다시 호출합니다(임시저장이 중복으로 쌓이지 않음).
- **2단계 응답이 깨졌거나 비정상으로 짧음**(머리말 없음, 본문 구획 없음, 제목 후보 3개 미만, 초안의 60%보다 짧음) → `2단계 검수 응답이 규격을 벗어나(사유) 1단계 초안을 표시합니다`로 초안을 유지합니다.
- 2단계도 1단계와 **같은 `parseResult()` 파서**로 읽고, 같은 10대 규격(첫 줄 `## 제목 후보`)을 유지하도록 프롬프트에서 강제합니다. 2단계 온도는 0.25로 낮춰 문장을 새로 쓰지 않고 지침 위반만 고치게 합니다.
- 단계별 제한 시간 3분(`BS.TWO_STAGE.stageTimeoutMs`), 검증 기준은 `BS.TWO_STAGE.minAuditChars`·`minAuditRatio`.

## 무료 한도 자동 모델 전환 (v1.6.1 · 2026-11-17)
기본 모델의 무료 한도가 끝나면 **설정을 건드리지 않아도** 무료 500편 모델로 자동 전환해 1단계 초안과 2단계 검수를 끝까지 이어 갑니다.

| 상황 | 앱이 하는 일 |
|---|---|
| **429 일일 한도**(`GenerateRequestsPerDay…FreeTier`) | 한도가 끝난 모델은 건너뛰고 바로 다음 무료 모델로 다시 호출 |
| **429 분당 한도**(`…PerMinute…`) | 같은 모델을 짧게(기본 5초, 최대 8초) 기다렸다 한 번 더 시도. 그래도 막히면 다음 모델로 |
| **404 모델 없음/미지원** | 설정에 남은 옛 모델명이어도 다음 무료 모델로 넘어가 계속 작성 |
| **1단계 후 2단계** | 1단계에 실제로 쓰인 모델로 2단계를 시작합니다(한도 끝난 모델을 다시 부르지 않음) |
| **전환 사실 안내** | 결과 위 배너에 `🔀 … 한도에 닿아 … 모델로 자동 전환해 이어서 작성합니다…` → 완료 뒤 `기본 모델 한도에 도달해 무료 넉넉한 모델(Flash Lite)로 자동 전환해 작성했습니다 (gemini-2.5-flash → gemini-3.5-flash-lite)` |
| **모두 소진** | `무료 한도에 걸려 쓸 수 있는 모델을 모두 확인했습니다 — 모델(429) → 모델(429) … 무료 한도는 태평양시 자정(한국 시간 오후 5시 무렵)에 다시 채워집니다`로 알림 |
| **자동 전환 끄기** | `⚙️ 설정`의 **한도가 끝나면 다른 무료 모델로 자동 전환** 체크를 풀면 예전처럼 429 오류로 바로 알립니다(기본 켜짐) |

### 키워드는 어떻게 만들까
`tools/fetch_realtime_trends.py`가 무료 공개 소스만 모아 **4대 블로그 조건으로 자동 분류**합니다(유료 API·키 없음).

| 소스 | 얻는 것 |
|---|---|
| 구글 트렌드 한국 RSS (`trends.google.com/trending/rss?geo=KR`) | 급상승 검색어 + 관련 기사 |
| 시그널 실시간 검색어 API (`api.signal.bz/news/realtime`) | 실시간 검색어 10 + 순위 변동 |
| 네이버 많이 본 뉴스 + 섹션 면(경제·생활/문화·IT) | 헤드라인 → 키워드 |
| 네이트 언론사 랭킹 | 헤드라인 → 키워드 |
| 연예·생활 / 건강 전문지 RSS | 생활픽스·긍정사랑 키워드 보충 |

- 분류 사전은 `LEXICON`(생활/경제/식단·건강/질병)에 있고, 기사 제목에 걸린 말을 그 블로그의 **쓸 수 있는 주제어**로 바꿉니다(예: `주담대`→`주담대 금리`, `치매`→`치매 초기증상`).
- 정치·사건·사고성 키워드는 **주제어로 올리지 않고** 아래 `주요 뉴스`에만 남깁니다(블로그에 쓸 수 없는 말로 주제칸을 채우지 않게).
- 블로그마다 최소 6개, 전체 34개 안팎 + 4대 블로그 밖 이슈 8개(배지 `이슈`, `전체` 탭에만)를 점수순으로 담습니다.
- 한 소스가 죽어도 나머지로 계속 만들고, 화면 아래에 `N곳 일시 실패`로 표시합니다. 전부 실패하면 기존 JSON을 덮어쓰지 않습니다.

### 자동 갱신
`.github/workflows/realtime-trends.yml` (정의 원본은 `tools/realtime-trends.workflow.yml`)
- `cron: "10 * * * *"` — **매시 10분** 자동 수집, `workflow_dispatch`로 손으로 한 번 실행 가능
- 바뀐 내용이 있을 때만 `data/realtime-trends.json`을 커밋합니다(`permissions: contents: write`)
- 손으로 돌려 보기: 저장소 → Actions → `실시간 키워드 수집` → Run workflow, 또는 `gh workflow run realtime-trends.yml`
- **켜는 방법(한 번만)** — Pickle의 GitHub 연결에는 `workflows` 권한이 없어 이 파일은 자동 push가 막힙니다(2026-11-17).
  1. GitHub → 이 저장소 → **Add file → Create new file**
  2. 이름에 `.github/workflows/realtime-trends.yml` 입력
  3. `tools/realtime-trends.workflow.yml` 에서 머리 주석(첫 `# ───` 줄까지)을 뺀 나머지를 붙여 넣고 Commit
  4. Commit 하면 그때부터 매시 10분에 자동 갱신됩니다 (첫 실행은 Actions 탭 → Run workflow)

### 가독성·빈줄 여백 (v1.5.2 · 2026-11-17)
네이버 스마트에디터 ONE은 붙여넣을 때 CSS `margin`을 거의 지워서 글이 한 덩어리로 붙어 보였습니다.
그래서 **글자가 아니라 빈 줄(`<p><br></p>`)로 여백을 만듭니다.**

| 위치 | 앱이 넣는 것 |
|---|---|
| 문단과 문단 사이 | 빈 줄 1줄 |
| 섹션 제목(`##`) 앞 | 빈 줄 2줄 (글의 큰 단락이 한눈에 나뉨) |
| 소제목(`###`) 앞 / 아래 | 앞 2줄 / 아래 1줄 + 굵게·큰 글씨 |
| 목록·표·인용(제휴 팁) 앞뒤 | 빈 줄 1줄 |
| `3초 핵심정리` 박스 안 | 제목과 항목 사이 빈 줄, 항목 간 10px |
| 긴 문단 | 100자(공백 포함)를 넘으면 문장 단위로 끊어 문단 2~3개로 분리 (글자는 그대로) |
| 해시태그 앞 | 빈 줄 2줄 |
| 연속 빈 줄 | 어떤 경우에도 3줄 이상 넣지 않음(최대 2줄) |

## 형광펜 2색 + 굵게 강조 (v1.7.2 · 2026-11-17)
지연님이 스마트에디터 화면 두 장을 보내며 "상황에 따라 이렇게 표시도 해 줄 수 있어?"라고 물었습니다. 한 장은 '첫째·둘째·셋째 요점 문장'에 노란 형광펜이, 다른 한 장은 핵심 결론은 노란색·체크 조건은 연한 하늘색이 칠해져 있었고, "다른 중요한 단어나 문장은 굵게 표시"도 함께 요청했습니다.
그래서 원고를 쓰는 AI는 **기호로만 표시**하고, 앱이 화면과 스마트에디터 복사본에서 색으로 바꿉니다.

| 표시 | 기호 | 색 | 쓰는 자리 |
|---|---|---|---|
| 노란 형광펜 | `==문장==` | `#fff3a3` | 핵심 결론, 첫째·둘째·셋째 요점 문장 |
| 하늘 형광펜 | `@@문장@@` | `#d9f3f4` | 꼭 확인할 조건·주의사항·체크포인트 문장 |
| 굵게 | `**단어**` | — | 형광펜 밖 본문 속 중요한 단어·숫자·금액·기한 |

- 남발 금지: 노랑+하늘을 합쳐 **4~8문장(소제목당 1~2문장)**, 굵게는 문단마다 1~2곳. 1단계 프롬프트·2단계 검수표가 같이 봅니다.
- 형광펜은 **본문 문장에만** — 제목·소제목·목차·표 안·해시태그·출처·면책사항에는 쓰지 않습니다.
- 하늘색 기호로 `@@`를 고른 이유: 이메일 주소(`a@b.com`)에는 홑@만 있어 겹치지 않고, `~~`·`__`·`^^`처럼 본문에 우연히 나올 일도 없습니다. 문장 안의 `1+1=2` 같은 등호도 건드리지 않습니다.
- 앱이 하는 일
  - 미리보기: `<mark class="bs-hl">` · `<mark class="bs-hl-blue">` (style.css)
  - 스마트에디터 복사본: `<mark style="background-color:#fff3a3;color:inherit">` — 붙여넣을 때 배경색이 살아남는 인라인 방식, 굵게는 `<strong style="font-weight:700">`
  - 형광펜 안의 `**굵게**`는 겹쳐도 깨지지 않습니다(예: `==**추가 비용**은 계약서에 적어야 해요.==`)
  - 짝이 안 맞는 `==`·`@@` 기호는 화면·복사본에 남기지 않고, 마크다운·제목 복사본(순수 텍스트)에서는 형광펜 기호를 지우고 `**굵게**`는 마크다운 서식으로 남깁니다

검증: `python3 work/bs172-test/test_highlight.py` **70항목 통과** (문법·미리보기·복사본 인라인·중첩·이메일/링크 보호·순수텍스트·프롬프트·버전/캐시) · 렌더 증빙 `python3 work/bs172-test/shot_highlight.py` → `browser/v172_highlight_preview.png`·`v172_highlight_richcopy.png` (실측 노랑 rgb(255,243,163) · 하늘 rgb(217,243,244) · 형광펜 안 굵게 700) · 기존 회귀 `rich_spacing_test.py` 38항목·`test_center_align.py`·`affiliate_skip_test.py` 24항목·`legacy_test.py` 모두 통과.

### 2) 원클릭 글쓰기 연결
카드의 버튼을 누르면 글쓰기 화면으로 넘어가면서 자동으로 채웁니다.

| 버튼 | 하는 일 |
|---|---|
| ✍️ 이걸로 글쓰기 | 카테고리→블로그 자동 선택(음식·건강·여행=긍정예찬 / 금융=행복한긍정씨 / 나머지=생활픽스) · 주제칸 · 참고 링크/본문 · (상품이면) 🛒 제품 리뷰 모드 + 제품 메모·리뷰 모듈 |
| ⚡ 원고+멀티유즈 | 위와 같고, **원고가 나오면 ⚡ 멀티유즈**(스레드 훅·첫 댓글 + 클립 20초 자막)가 자동으로 이어집니다 |

- 이어서 돌 작업은 글쓰기 화면의 `🔥 … 카드에서 왔습니다` 줄에서 **체인 끄기**로 취소할 수 있습니다.
- 생성이 실패하면 체인은 돌지 않습니다.

### 3) 🔄 새로고침 — 그 자리에서 즉시 수집
1. 먼저 `data/hot-items.json` · `data/realtime-trends.json`을 **캐시 무시**(`?t=…`)로 다시 읽습니다.
2. ⚙️ 설정에 **GitHub 토큰**이 있으면 `POST /repos/mama2624/blog-studio/actions/workflows/realtime-trends.yml/dispatches` (`{"ref":"main"}`)로 수집을 트리거하고, `지금 새로 수집 중… (약 20~40초)`를 띄운 뒤 **5초마다** run 상태를 확인합니다.
3. run이 `completed`(success)가 되면 GitHub API에서 커밋된 `data/realtime-trends.json`의 `hotItems`를 바로 받아 화면에 반영합니다(Pages 재배포를 기다리지 않음). 실패·시간 초과는 사유와 함께 안내합니다.
4. 토큰이 없으면 최신 JSON만 다시 읽고 **"즉시 수집을 쓰려면 ⚙️ 설정에서 GitHub 토큰을 한 번만 등록해 주세요"** 안내와 설정 열기 버튼을 띄웁니다.

**토큰 준비(한 번만)**
- GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens**
- Repository access: **Only select repositories → mama2624/blog-studio**
- Permissions: **Actions: Read and write** (그 외 권한 불필요)
- 발급한 토큰을 작업실 ⚙️ 설정 → **GitHub 토큰** 칸에 붙여넣고 저장
- 토큰은 이 브라우저의 `localStorage('bs.ghToken')`에만 저장되고 **코드·깃허브에는 절대 들어가지 않습니다**. 지우기 버튼도 있습니다.

### 4) 수집·갱신 구조
| 파일 | 역할 |
|---|---|
| `tools/fetch_hot_items.py` | 클리앙 알뜰구매 1페이지 + 핫허브 RSS 파서 · 카테고리/블로그 배정 · 점수 · `data/hot-items.json` 스냅샷 + 하루치 이력(저장소 제외) |
| `tools/fetch_realtime_trends.py` | 기존 매시 수집에 `current_hot_items()`를 붙여 `data/realtime-trends.json`의 `hotItems` 필드로 함께 실어 보냄(새 워크플로 파일을 못 만들어서) |
| `.github/workflows/realtime-trends.yml` | `schedule` 매시 10분 + `workflow_dispatch`(작업실 🔄가 쓰는 통로) · `data/realtime-trends.json` 커밋 |

- 워크플로는 **이미 `workflow_dispatch`가 있고 `fetch_realtime_trends.py`를 돌리므로 손대지 않았습니다** — 이 저장소 연결(Pickle GitHub App)에 `workflows` 권한이 없어 워크플로 파일 수정은 푸시가 거부됩니다. 화제템은 그 스크립트가 같이 수집해 `realtime-trends.json`의 `hotItems`로 커밋되므로 그대로 동작합니다.
- `data/hot-items.json`은 배포 시점 스냅샷(예비)이라 매시 갱신되지 않습니다. 앱은 둘 중 새 것을 읽으므로 화면은 항상 최신입니다.

- 앱은 두 파일 중 `generated_at`이 **더 새로운 쪽**을 읽습니다. 3시간(180분)이 지나면 화면에 '오래된 자료' 경고가 뜹니다.
- 하루치 이력(`data/hot-items-history/`)은 앱이 읽지 않으므로 `.gitignore`로 저장소에는 올리지 않습니다.
- 넣지 않은 소스(2026-11-18 실측 차단): 쿠팡 403 · 알구몬 Cloudflare · 뽐뿌 403 · 다나와·올리브영 403 · 네이버 데이터랩(robots Disallow) 등.

검증: `python3 work/bs210-test/test_v210.py` **166항목** · 실서버 `python3 work/bs210-test/live_check.py` → `browser/v210_hot_items.png` · `browser/v210_hot_items_mobile.png`
